From Problem to Practice

Digital innovation framework for educational environments.

This is a digital innovation framework, not an artificial intelligence development framework. It provides a consistent path from identifying an operational difficulty through to testing and evaluation. It does not assume or imply that every project reached implementation.

1. Problem Discovery

Identify a clear educational, accessibility or operational problem. Possible sources include:

  • User feedback
  • Teaching practice
  • Assessment processes
  • Accessibility requirements
  • Service information[cite: 1]
  • Research evidence[cite: 1]

2. Investigation

Review the practical parameters of the problem[cite: 1]:

  • The people affected[cite: 1]
  • The existing process[cite: 1]
  • Available evidence[cite: 1]
  • Current products or services[cite: 1]
  • Risks and limitations[cite: 1]
  • Technical feasibility[cite: 1]

3. Proof of Concept

Develop a focused version that tests the central idea[cite: 1]. The proof of concept should answer[cite: 1]:

  • Can the proposed function work?[cite: 1]
  • Is it relevant to the original problem?[cite: 1]
  • Is further testing justified?[cite: 1]

4. Pilot

Test the product with an appropriate user group in a realistic setting[cite: 1]. A pilot may examine[cite: 1]:

  • Usefulness[cite: 1]
  • Clarity[cite: 1]
  • Trust[cite: 1]
  • Accessibility[cite: 1]
  • User experience[cite: 1]
  • Educational relevance[cite: 1]
  • Operational feasibility[cite: 1]

5. Evaluation

Collect and analyse suitable evidence[cite: 1]. Evidence may include[cite: 1]:

  • Survey responses[cite: 1]
  • Interviews[cite: 1]
  • Focus groups[cite: 1]
  • Usage information[cite: 1]
  • Observation[cite: 1]
  • Open-text feedback[cite: 1]
  • Quality review[cite: 1]

6. Implementation Decision

Use the evidence to decide whether the project should[cite: 1]:

  • Progress[cite: 1]
  • Be revised[cite: 1]
  • Be integrated with another service[cite: 1]
  • Remain exploratory[cite: 1]
  • Stop[cite: 1]

7. Improvement

Refine the project using user feedback, evidence, accessibility requirements and changes in context[cite: 1].
